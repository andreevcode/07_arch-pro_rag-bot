# Задание 2. Подготовка базы знаний
> Теперь вам нужно создать собственную базу знаний, с которой LLM не сталкивалась при обучении. Так вы сможете гарантировать честную работу механизма RAG. Это будет ваш локальный корпоративный мир, невидимый внешнему ИИ.

## Что нужно сделать?
>1. Выберите предметную область
>   - Возьмите открытый фандом или тематическую вики (например, starwars.fandom.com).
>   - Выберите 30+ страниц по ключевым сущностям: персонажи, объекты, технологии, события.

- Для задания выбрана [фанбаза по Звездным войнам на русском языке](https://starwars.fandom.com/ru/wiki/Заглавная_страница). Отобрано 30 статей (частично или целиком) по разным тематикам: `characters, events, places, tech`.
- Сформированная сырая база знаний расположена в [task2/raw_db/data](raw_db/data).
>2. Скачайте и очистите тексты
>   - С помощью Python-скрипта или вручную получите из этих страниц чистый текст (без HTML и лишнего форматирования).
>   - Разбейте каждый документ по темам (один файл — одна сущность).`
- документы сохранены в markdown, при этом удалены спец.символы, лишнее форматирование;
- при этом проставлены заголовки 1,2 и 3 уровня, для использования в качестве метаданных позже;

>3. Замените ключевые термины. Соберите словарь соответствий.
>   Например:
>   "Darth Vader" → "Xarn Velgor"  
>   "Death Star" → "Void Core"  
>   "The Force" → "Synth Flux"   
>   - Используйте скрипт для замены всех упоминаний терминов в текстах.
>   - Убедитесь, что тексты остались логичными и читаемыми, но больше не распознаются как относящиеся к вселенной Star Wars.
- составлен словарь переименований терминов [terms_map.json](raw_db/terms_map.json); тематика переименования: теннисный мир, использованы реальные имена теннисистов и термины;
- python скрипт [replace_terms.py](raw_db/replace_terms.py) создает на основе сырой базы базу знаний для RAG, где часть персонажей, событий, технологий и т.п. переименованы;
- цель замены терминов: протестировать, что конечный бот будет использовать знания именно из RAG модели, а не знания, которые LLM получила во время обучения; 
  - >большинство открытых источников (фандомы, Википедия и т. д.) уже попали в датасеты при обучении LLM, поэтому, если, например, по вопросу про Дарта Вейдера модель ответит по памяти, не обращаясь к базе знаний, а значит, задание утратит смысл.
- пример запуска скрипта из корня `task2`:
    ```sh
    python raw_db/replace_terms.py \\  
        --src raw_db/data \\  
        --dest knowledge_base \\  
        --terms raw_db/terms_map.json
    ```

> 4. Сохраните уникальную базу
>    - Папка `knowledge_base/`, в ней — очищенные и переименованные .txt или .md документы (30+ штук).
>    - Дополнительно ещё `terms_map.json` со словарём замен (исходное → вымышленное).
- итоговая база статей для RAG расположена тут: [knowledge_base](knowledge_base).
- словарь [terms_map.json](raw_db/terms_map.json) и база знаний [knowledge_base](knowledge_base) и была перегенерированы несколько раз из-за неидеальной работы скрипта переименования; ошибки находились вручную или по результатам тестирования запросов к LLM в задании 4.


## Важный нюанс (и спойлер):
- названия файлов не менялись после переименования терминов, т.е. Дарт Вейдер был переименован в Роджера Джоковича (aka Роджер Федерер + Новак Джокович), но документ остался с наименованием `Вейдер.md`;
- далее в задании 3 формировались метаданные для RAG, куда включались названия файлов, а на этапе тестирования бота в связке LLM + RAG выяснилось, что модель начинает галлюцинировать, используя оригинальные термины из фанфика на основе только метаданных; 
- пример галлюцинации: на вопрос "Кто такой Дарт Вейдер" LLM мог ответить, что Вейдер - это Роджер Джокович;
- корректировка инструкций в промпте LLM не помогла, говорят, что метаданные с названиями файлов являются корневыми данными для LLM;
- итоговое решение: пришлось убрать оригинальные названия файлов из метаданных;
- в реальной ситуации вероятно, названия документов не должны отличаться от содержимого, поэтому проблемы не будет;
