## Задание 4. Реализация RAG-бота с разными техниками промптинга
- Настроить работающий RAG-пайплайн:
    - выбрать LLM для промтинга (внешнюю, внутреннюю);
    - сервис `RAG-api`, реализующий:
        - загрузка поискового индекса в `ChromaDb`;
        - подключение клиента к внешней `LLM`;
        - прием текстового запроса;
        - преобразование запроса в эмбеддинг;
        - поиск эмбеддинга в индексе RAG и получение топ-N чанков;
        - промтинг (отправка запроса с результатами поиска в LLM) c помощью нескольких техник: zero-shot, few-shot, CoT;
        - тестирование для 3–5 примеров диалогов, в том числе когда `RAG-api` будет отвечать "не знаю";
        - фиксация результатов;
    - телеграм-бот `telegram-rag-sw-bot` в качестве дополнительного интерфейса к `RAG-api`;
    - протестировать RAG на реальных запросах и решить возникающие проблемы;

## Задание 5. Демонстрация работы бота в части обеспечение безопасности
Бот работает, в этом задании нужно обеспечить, чтобы он не выдавал чувствительную информацию и был способен противостоять атакам через KB (knowledge base):
- загрузить злонамеренные файлы в базу знаний;
- посмотреть, как могут утекать данные;
- рассмотреть и внедрить разные уровни защиты:
    - Pre-prompt: добавление инструкций безопасности в промпт;
    - Post-retrieve: функция, отбрасывающая чанки с потенциально вредоносным содержимым;
    - Post-retrieve: очистка текста в чанках от опасных и конфиденциальных данных;
- протестировать разные способы защиты и проанализировать результаты;
- подробное описание решений: [TASK5_README.md](task5/TASK5_README.md);

## Задание 6. Автоматическое обновление базы знаний
Вам нужно полностью автоматизировать процесс обновления базы знаний: скачивание новых документов, преобразование их в чанки, обновление векторного индекса и логирование. Если реально использовать RAG в продукте, то вы неизбежно столкнётесь с тем, что живые данные быстро устаревают. Поэтому:
- выберите источник данных;
- напишите скрипт обновления индекса, можно использовать Python, bash, make, invoke, airflow — на выбор; главное — автоматизм;
- настройте периодический запуск;
- реализуйте логирование;
- нарисуйте архитектурные диаграммы контейнеров и компонентов, используя `PlantUML`;
- подробное описание решений: [TASK6_README.md](task6/TASK6_README.md);

- составить золотой список вопроосов, часть из которых должны деградировать при изменениях в Базе;
- внести пробелы в KB с целью тестирования качества покрытия;
- написать скрипт для автоматического тестирования и сохранения логов покрытия RAG;
- произвести анализ логов (у меня перед этим расчет метрик расчет метрик RAG);
- нарисовать диаграмму последовательностей процессов RAG;
